# R8 / ProGuard

retrofit-graphql is R8-safe when using the recommended kotlinx.serialization path. This page documents the R8 configuration from the sample app and guidance for different serialization configurations.

## R8 Configuration (Sample App)

### Enable R8

```kotlin
// app/build.gradle.kts
android {
    buildTypes {
        getByName("release") {
            isMinifyEnabled = true
            isShrinkResources = true
        }
    }
    testBuildType = "release"  // test against R8-optimized APK
}
```

### kotlinx.serialization: No Keep Rules Needed

The kotlinx.serialization compiler plugin **automatically** generates R8 consumer rules that protect `@Serializable` classes and their serial descriptors. No custom keep rules are required for:

- Generated response DTOs (`GetCurrentUserData`, `GetMarketPlaceAppsData`, etc.)
- `GraphContainer<T>` (provided `T` is `@Serializable`)
- `GraphError` and `GraphError.Location`
- `GraphQLRequest<TVariables>` (serialization side)
- `EmptyGraphQLVariables`
- Any enum, variable, or input object class generated by the codegen plugin

### Gson Upload Path: 2 Targeted Keep Rules

The sample app uses Gson for the multipart upload path (`UploadMutationHelper`). Gson derives JSON keys from `java.lang.reflect.Field.getName()`, so field names must survive R8 renaming:

```proguard
# app/proguard-rules.pro

# GraphQLRequest: serialized by Gson in UploadMutationHelper.createOperationsPart()
-keep class co.anitrend.retrofit.graphql.model.GraphQLRequest {
    <fields>;
    <init>(...);
}

# UploadToStorageBucketVariables: serialized by Gson as nested variables
# within the operations payload of a multipart upload request.
-keep class co.anitrend.retrofit.graphql.sample.bucket.UploadToStorageBucketVariables {
    <fields>;
    <init>(...);
}
```

These rules are **narrowly scoped** to the exact classes used in the Gson upload path. The `-keep` directive preserves the class and all its members (fields, methods) so Gson's reflective serialization works correctly.

### APQ + Gson Trap

If you use `withPersistedQuery()` in the Gson upload path, `PersistedQuery` is serialized as part of the request. Add:

```proguard
-keep class co.anitrend.retrofit.graphql.model.request.PersistedQuery {
    <fields>;
}
```

This is only needed if your Gson path involves APQ. The typed kotlinx request path supports `withPersistedQuery()` because `KotlinxGraphQLJson.encode()` merges supported `extensions` values into the outgoing JSON.

## Verification

### Unit Tests (R8)

```bash
./gradlew :app:testReleaseUnitTest
```

This runs unit tests against the R8-optimized APK. The sample app has 11 unit tests (6 serialization + 5 mapper) that validate:

- `GetCurrentUserData` can be deserialized from JSON
- `GetMarketPlaceAppsData` can be deserialized from JSON
- `@SerialName` annotations survive R8
- Error responses deserialize with R8-optimized classes
- Empty data responses deserialize with R8-optimized classes

### Instrumented Tests (R8 on Device)

```bash
./gradlew :app:connectedReleaseAndroidTest
```

The `ReleaseSerializationTest` instrumented test validates serialization behavior on an actual device/emulator running the R8-optimized APK.

### Mapping Inspection

```bash
# Check what R8 renamed
cat app/build/outputs/mapping/release/mapping.txt
```

Verify that no serialization-critical classes or fields are renamed:

- Generated response DTO classes should be present (not renamed) if kotlinx consumer rules are working
- `GraphQLRequest` fields (`query`, `operationName`, `variables`) should not be renamed
- `UploadToStorageBucketVariables` field (`upload`) should not be renamed

## What NOT to Keep

You do **not** need keep rules for:

- Generated response DTOs (`*Data` classes) -- protected by kotlinx consumer rules
- `GraphContainer`, `GraphError`, `EmptyGraphQLVariables` -- all `@Serializable`, protected by kotlinx consumer rules
- Retrofit interfaces -- Retrofit ships its own consumer rules
- OkHttp/Okio types -- they ship their own consumer rules

## Full Gson Path

If your project uses Gson for the entire Retrofit path (no kotlinx), you need keep rules for every class serialized/deserialized by Gson. The library ships consumer rules from `:library` for its own types, but your model classes need their own rules:

```proguard
# Your Gson-serialized model classes
-keep class com.your.app.model.** {
    <fields>;
}
```

Consider migrating to kotlinx (`:serialization-kotlinx`) for zero-config R8 safety.
